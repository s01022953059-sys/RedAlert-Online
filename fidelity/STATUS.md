# 原版还原验收状态

结论：未达标。原型不作为原版实现继续扩展。尚无可报告的整体百分比。

## 引擎调查

候选：https://github.com/TheAssemblyArmada/Vanilla-Conquer
已检出研究版本：ce83b59edd99cccac6cebaae054ca04962c744b7。
README 描述其为原版第一代引擎的跨平台版本；当前检出的 CMakeLists.txt 使用 SDL2/OpenAL，未发现现成 Emscripten 配置。尚未编译或运行这个引擎，不能宣称 WebAssembly 可用或与零售版行为完全一致。

不把 DOSBox/DOS 版运行结果替代 Windows 版验收，不把 OpenRA 规则替代原版规则。保留原版逻辑的移植仍需要处理平台 I/O、浏览器事件循环、文件系统、输入、音频、视频与持久化，并对每项改变做回归。

## 缺失基准

当前云端没有 Windows 原版游戏程序与素材，也没有独立运行的同版本原版参考输出。旧会话中的 1997 Demo 位于另一执行环境，本环境无法访问；不能直接当作零售版基准。REA 工具与先前证据尚未取得。

用户的 99.99% 要求保留，但没有定义可覆盖全部体验的统计分母。单张图像的像素比例不能作为整体游戏还原度。未经用户确认，不用加权平均掩盖功能缺失。

## 验收门槛

- 版本：语言、发行版本、补丁、EXE 与全部资源的 SHA-256 清单；基准需可独立运行。
- 视觉：原始分辨率、相同场景/帧/调色板；逐帧输出差异图。开场、菜单、建造栏、地图、单位和动画逐项记录。
- 逻辑：相同地图、随机种子、帧序命令；逐 tick 对照资金、生产完成时刻、坐标、生命值和事件。不一致必须记录，不能凭截图放行。
- 音视频：声音触发、采样、音乐与影片完整性及时间关系。
- 功能：原版任务、AI、存读档及要求覆盖的其他模式逐项验证。
- Web 平台：浏览器输入、缩放、暂停、后台恢复、文件持久化实测。

## 工具

`python3 fidelity/inventory.py /path/to/game > baseline.json`：只读清点文件并计算 SHA-256，不运行游戏，不上传资源。

`python3 fidelity/compare.py reference.png candidate.png --diff diff.png`：只接受同尺寸帧，生成精确像素差异与平均通道误差。只证明该帧的数值差异。

依赖 Pillow。`python3 -m unittest discover -s fidelity -p 'test_*.py'` 测试比较器与清点器。

必须取得原版程序/素材和独立参考运行结果后才能完成对照；本目录不是新的游戏交付或达标证明。未更改任何部署通道或基础设施。
